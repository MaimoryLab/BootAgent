# 工具市场在线更新实施规范

## 目标

工具市场以嵌入式静态目录为稳定基线，并通过后端适配器增量发现 SkillHub 与 MCP
Servers 的公开数据。用户看到的卡片不能因为网络、缓存或某个数据源失败而消失；
搜索、筛选和滚动必须属于同一个查询会话，不能把不同查询的结果混在一起。

## 当前问题

- 首次进入只请求一次第一页，没有主动刷新入口或定时刷新。
- 磁盘缓存有效期过长时会短路网络请求，用户无法快速获取 SkillHub 更新。
- SkillHub 与 MCP 共用一个 offset，来源数量不同会导致跳页或截断。
- 请求没有查询版本，旧请求晚返回时可能覆盖新搜索结果。
- 滚动区域是 `.page-body`，监听 `window` 会使分页和虚拟列表失效。

## 设计决策

### 查询会话

前端为每次关键词、来源或分类变化生成递增的查询序号。请求携带完整查询条件；
响应只在序号仍然匹配时写入状态。查询序号不是安全凭据，只用于丢弃过期响应。

### 来源级分页

SkillHub 和 MCP Servers 各自维护 `offset`、`has_more` 和 `total`。后端一次请求只
访问指定来源的一页，返回 `next_offset`。前端不得根据返回条数猜测下一页，也不得
用一个来源的分页游标请求另一个来源。

### 搜索与筛选

- 关键词搜索传给远程适配器；SkillHub 使用 `keyword`，MCP 适配器在本地页内匹配，
  必要时继续读取有限页以找到未加载的结果。
- 分类、场景、工具类型等产品维度在统一卡片集合上执行；不支持远程映射的维度不
  得伪装成远程精确筛选。
- 滚动请求复用当前查询条件和查询序号。

### 刷新与缓存

- 首次进入立即请求第一页；有效磁盘缓存只能作为失败回退，不能阻止首屏网络请求。
- 提供用户可触发的强制刷新，并在页面停留期间按 10 分钟间隔后台刷新第一页。
- 无查询条件的第一页使用 ETag；304 时复用缓存并更新抓取时间。
- 刷新期间保留现有卡片，不能显示空白页。

### 合并规则

- 静态目录优先，动态卡片追加在静态卡片之后。
- 以稳定 ID 去重，再以 `source + normalized name` 做跨版本兜底去重。
- 动态源失败时保留静态卡片，并在数据源状态中显示 `cached` 或 `unavailable`。

## API 契约

`MarketplaceService.DiscoverSources` 接收：

```json
{
  "source": "skillhub",
  "query": "",
  "category": "",
  "limit": 50,
  "offset": 0,
  "force_refresh": false,
  "query_id": "q-12"
}
```

响应至少包含：

```json
{
  "items": [],
  "sources": [],
  "total": 0,
  "has_more": false,
  "next_offset": 0,
  "query_id": "q-12",
  "stale": false,
  "fetched_at": ""
}
```

`sources` 中每个来源必须报告 `id`、`state`、本次或缓存的 `item_count`、
`total`、`fetched_at` 和可展示的错误摘要。错误摘要不得包含响应正文、密钥或本地
敏感路径。

## 验收标准

- [x] 首次进入市场在一个请求窗口内显示静态卡片，并开始请求 SkillHub 第一页。
- [x] 点击刷新会跳过新鲜缓存；网络失败时已有卡片仍可浏览。
- [x] SkillHub 与 MCP 分别滚动分页，无重复、无跳页、无强制截断。
- [x] 搜索一个首屏未加载但远端存在的 Skill/MCP 能返回统一卡片。
- [x] 快速连续搜索时，旧响应不会覆盖最后一次查询。
- [x] 切换分类/来源后，结果只属于当前条件，静态基线不消失。
- [x] 真实 Wails 浏览器测试覆盖加载、刷新、搜索、滚动和错误回退。
- [x] `go test ./...`、`go vet ./...`、前端全量测试、类型检查和生产构建通过。

## 实施记录

- 后端为 SkillHub 与 MCP Servers 建立独立来源适配器、分页游标、查询 ID、强制刷新、
  ETag 和受限缓存回退；静态目录始终作为首屏基线。
- 前端以查询会话隔离请求，按来源并发分页，滚动触发后续页；短结果集会有限度自动
  补页，避免本地场景/类型筛选后没有滚动事件而永远看不到后续匹配项。
- 卡片以静态目录优先、动态结果追加，并按 ID 与来源/名称去重；详情页携带动态卡片
  快照，后续页的工具不会因重新创建查询而丢失详情。
- 数据源状态显示实时/缓存/不可用及已加载数/总数；刷新期间保留已有卡片。
- 设置页的版本 binding 增加字符串边界校验，避免浏览器预览或旧 binding 返回结构化
  错误对象时导致 React 渲染崩溃。

## 验证结果

- Go：`go test ./...`、`go test -race ./...`、`go vet ./...`、`staticcheck ./...`。
- Frontend：498 个 Vitest 用例通过，`pnpm run typecheck` 与 `pnpm run build` 通过。
- 回归：新增 MCP 无效记录跨页扫描、SkillHub 空页游标推进、过期查询隔离、强制刷新、
  本地筛选自动补页和静态基线保留用例。
- 浏览器：Playwright Wails server 模式覆盖市场加载、刷新、搜索、分页/筛选和详情路由；
  生产桌面构建另行在本机启动验收。

## 风险与边界

- SkillHub 总量很大，禁止为了刷新首屏遍历全量页面；后台刷新只拉第一页，后续由
  用户滚动驱动。
- 外部 API 是公开但非稳定协议，所有字段必须容错解析，适配器失败不得阻塞静态市场。
- 本地埋点只保存聚合事件，不记录搜索正文、URL 查询中的密钥或 README 内容。
