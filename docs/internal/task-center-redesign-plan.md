# 安装与更新任务中心改造计划

## 目标

将安装、运行时下载、Agent 更新、BootAgent 自更新统一为可追踪的任务体验。用户需要持续知道：任务在做什么、下载来自哪里、进度如何、失败原因是什么，以及应用重启后如何找回结果。

## 当前基线与假设

1. 任务中心由 React `TaskCenterProvider` 管理，Wails 通过 `InstallOutput` 推送实时事件。
2. 安装和更新仍由 Go 用例负责，React 不直接执行子进程或网络请求。
3. API Key、完整 prompt、私密配置和未经脱敏的命令参数不得进入任务持久化或普通日志。
4. 第一阶段优先保持现有安装流程兼容，不引入新的数据库依赖。

## 分阶段范围

### 阶段一：任务可观测性

统一任务模型和事件模型，补齐以下信息：

- 任务阶段：准备、选择来源、下载、校验、安装、配置、完成、失败。
- 目标名称、版本、锁定版本和任务类型。
- 来源类型和来源主机；记录镜像尝试、回退和最终命中来源。
- 字节进度、速度、预计剩余时间；无 Content-Length 时使用不确定进度。
- 脱敏错误码、退出码、是否可重试和用户可执行的下一步。

验收标准：任务卡片能在不打开详情页的情况下说明当前目标、阶段、版本、来源和进度；失败状态至少能区分网络、权限、校验、运行时缺失和子进程退出。

### 阶段二：任务详情页

新增统一的任务详情路由和展示模型：

- 时间线显示阶段变化、来源尝试、重试和校验结果。
- 多 Agent 安装按 Agent 分组显示独立结果、版本、Registry 和错误。
- 失败项支持独立重试，不能要求用户重新提交整个批次。
- BootAgent 更新显示“已下载、等待重启、重启中、已完成/回退”的明确状态。
- 日志默认显示脱敏摘要，支持展开完整脱敏日志和复制诊断信息。

验收标准：关闭安装向导后仍可从任务中心进入同一详情；多 Agent 中单项失败不会遮蔽成功项；更新下载完成但未重启时不会误报“更新完成”。

### 阶段三：任务持久化与恢复

增加本地任务记录存储，并定义生命周期：

- 保存运行中、成功、失败、取消和异常中断任务的元数据及脱敏日志。
- 应用启动时恢复未结束任务，无法确认进程状态的标记为“需要检查”，不能伪造成功。
- 保留最近任务并提供清理策略，限制记录数量、日志大小和单任务生命周期。
- 任务记录采用原子写入并收紧权限；禁止保存密钥、完整 prompt 和私密响应。
- 对已经完成且超过保留期的任务自动清理，用户可手动清除历史。

验收标准：应用重启后可看到最近任务和最终结果；异常退出不会造成任务状态丢失或错误恢复；存储损坏时应用仍能启动并给出可恢复提示。

## 边界与未决决策

- 始终遵守 Wails binding 是前后端唯一边界，生成文件禁止手改。
- 不在第一阶段引入远端遥测；任务记录仅保存在本机。
- 需要在阶段三开始前确定任务历史默认保留天数和最大日志大小。
- 需要在阶段二开始前确定“复制诊断信息”是否包含完整下载 URL，默认只复制来源主机和错误摘要。
