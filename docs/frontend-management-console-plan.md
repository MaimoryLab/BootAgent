# 前端管理控制台改造计划

把「跑完一次向导就结束」的界面改成能长期使用的管理控制台。四件事：Agent 品牌图标、总览减负、配置独立成页、侧边栏可用。

状态：待实施。范围只在 `frontend/`，不改 Python 内核与 API 契约。

## 0. 先纠正两个前提

**官方图标覆盖不全。** simple-icons（CC0）有 `claude`、`anthropic`、`opencode`、`cursor`，但 **Codex（openai）、Aider、Kilo 均为 404**。CC Switch 也只自带 `chatgpt.svg` 和 `claude.svg` 两个——它只管两个 Agent。因此不存在覆盖五个 Agent 的官方图标集，采用**混合方案**（已确认）。

**禁止 CDN。** `CLAUDE.md:72` 规定前端产物不得含 CDN 或远程字体引用，`cdn.simpleicons.org` 不能直接引用，所有图标必须内联进 bundle。

**商标边界。** CC0 只覆盖 SVG 文件本身，不覆盖商标权。在自己 UI 内标示「这一行是哪个 Agent」属指示性使用；不得把第三方 logo 用作 OneAgent 的产品视觉资产、启动图或营销素材。

## 1. Agent 图标

### 方案

`frontend/src/components/icons/agents.tsx` 集中导出图标组件，按 Agent ID 映射。来源分两类，但输出规范完全一致：

| Agent | 来源 |
| --- | --- |
| Claude Code | simple-icons `claude`（官方） |
| OpenCode | simple-icons `opencode`（官方） |
| Cursor 等 guide-only | simple-icons 对应条目（有则用） |
| Codex | 自绘（无官方图标） |
| Aider | 自绘 |
| Kilo CLI | 自绘 |

不装 `simple-icons` 依赖——只取需要的几条 `path` 数据内联，避免为 3 个图标引入一个几 MB 的包。每个 path 在源码注释里标注来源与 CC0。

### 统一规范（macOS 的做法：形状各异，容器一致）

- 视图框统一 `24×24`，渲染尺寸 `18`（列表）/`20`（详情页）。
- 单色 `currentColor`，由容器决定颜色，不使用品牌色——这是风格统一的关键，也顺带回避了 logo 变色的商标问题。
- 自绘图标笔画宽度对齐 lucide 的 `1.8`，官方图标为实心填充时降低不透明度到视觉重量相当。
- 复用现有 `.agent-icon` 容器（38×38 圆角方块）。

### 文字替换与 tooltip

列表里图标**替换**掉现在的 group 通用图标，Agent 名称保留为主标题（去掉名称不利于可访问性和搜索）。图标本身 `aria-hidden`，容器加 `title` 属性提供悬停说明，说明内容是 Agent 的一句话定位而非重复名称。

## 2. 总览减负

### 首屏被非内容占满（实测，1280×860）

| 元素 | 高度 | 起始 y |
| --- | --- | --- |
| `environment-summary`（含「开发环境已就绪」横幅 74px + 摘要网格 92px） | 184px | 171 |
| `overview-notice`（版本提示条） | 39px | 355 |
| 分区标题 | 40px | 420 |
| **Agent 列表** | — | **470** |

Agent 列表要到 y=470 才开始，**首屏 55% 的垂直空间没有实质内容**。用户打开首页，一半以上看到的是确认信息和提醒，真正要管理的五个 Agent 被挤到下半屏。

### 根本问题：一次性事件被固化成常驻横幅

- 「开发环境已就绪」是**向导跑完那一刻**的反馈。它属于激活页的完成态，不属于每天都要打开的管理页。
- 版本提示是**可延后的维护信息**，不是需要立刻处理的告警，却占着首屏最显眼的位置。

两者都不该长期消耗首屏视觉资源。

### 处理

**移除 `EnvironmentSummary`。** 它承载的 Provider / 模型 / 激活时间已经逐项显示在各 Agent 行里，per-Agent 之后这个"全局摘要"本身就是过时概念（各 Agent 可以指向不同 Provider，一个全局摘要无法表达）。向导完成的确认留在激活页，不跟到总览。

**版本提示降级为行内标记。** 删除 `overview-notice` 横幅，可更新的 Agent 直接在自己那一行显示 `0.144.4 → 0.145.0`。需要汇总时，标题旁一个小徽章「2 项可更新」即可，点击滚动定位，不占独立区块。

**分区标题合并。** 「已管理的 Agent」与页面标题「环境总览」语义重复，删除分区标题，列表直接跟在页面标题下。

目标：Agent 列表在 y≈150 内开始，首屏完整显示五个 Agent。

### 现存文案冗余（实测）

同一件事说了三遍：
- 页面描述：「每个 Agent 独立指向自己的 Provider 与模型，可随时单独调整。」
- 分区描述：「每一项的 Provider、模型和密钥互相独立，改动只影响该 Agent。」
- 空状态：「完成一次配置后，这里会列出每个 Agent 指向的 Provider 与模型，并可随时单独调整。」

### 处理

- 页面描述删除。标题「环境总览」加一行 Agent 列表已经自解释。
- 分区标题与描述一并删除（见上）。
- 空状态压到一句：「完成一次配置后，这里会列出每个 Agent 的指向。」
- 卡片内「已写入配置」这类状态标签改为图标加短句，不占独立一行。
- 版本状态用 `0.144.4 → 0.145.0` 的裸对比，去掉「可更新」三字——箭头已经表达了方向。

原则：**列表项只承载"是什么状态"，解释性文字移到需要时才出现的位置**。

## 3. 配置改为独立页面

这是本次最主要的结构改动。现在点「改配置」在卡片内展开面板，导致列表被撑长、多个面板可同时展开、状态散落。

### 路由

新增 `/agents/:agentId`，作为该 Agent 的管理详情页。总览的「改配置」改为跳转而非展开。

`AgentManageRow` 退化为纯展示行（图标、名称、指向、版本、状态徽章），移除内联面板、probe 状态和 apply 逻辑——这些搬到详情页。行本身可点击进入详情。

### 详情页内容

- 顶部：图标、名称、当前指向、版本状态、返回总览。
- 配置区：Provider 分段、Base URL（custom 时）、模型、API Key、测试连接、应用。逻辑从 `AgentManageRow` 平移，包括「探测通过才能应用」和「改 Key 作废上次结论」两条已验证的约束。
- 应用成功后显示重启指引与启动命令。
- 危险操作区（可选，本次不做）：清除该 Agent 配置。

### 收益

列表长度恒定；一次只有一个配置上下文；详情页有空间放版本、备份、配置文件路径等信息，而不必挤进一行。

## 4. 侧边栏

### Bug 根因

`NavigationSidebar` 把 `/setup/provider` 和 `/setup/review` 当作独立页面，但它们是被 `SetupGuard` 保护的**向导步骤**：未选 Agent 时守卫会重定向回 `/setup/agents`，所以点击像是没反应。这不是样式问题，是把流程步骤误当作了导航目的地。

### 改法（已确认：拆分独立页面）

侧边栏只保留真正的顶级页面：

| 项 | 路由 | 说明 |
| --- | --- | --- |
| 环境总览 | `/overview` | 已有 |
| Agent | `/agents` | 新增，Agent 列表（总览的列表部分独立成页，或与总览合并后此项指向总览） |
| Provider | `/providers` | **新增页面**：列出内置 Provider 与其 base URL、哪些 Agent 正在用它、连通性测试入口 |
| 配置模板 | `/profiles` | **新增页面**：`profiles/` 模板的增删改，标注 `hasKey`，可应用到指定 Agent |

向导（`/setup/*`）从侧边栏移除，只由「激活环境」主按钮和首次运行进入。

`/providers` 与 `/profiles` 的数据后端已有：`status.providers`、`status.profiles`、`GET/POST /api/profiles`。不需要新 API。

### 空态

两个新页面都要有空态：Provider 页始终有内置项不会空；模板页无模板时给「从当前 Agent 配置创建模板」的入口。

## 5. 视觉规范（苹果与 Claude 设计语言）

现有 `tokens.css` 已是 macOS 风格（`#1d1d1f` 文字、`#007aff` 强调、`rgba(60,60,67,*)` 分隔线），继续用，不引入新色板。补充规范：

- **层级靠留白与字重，不靠边框和底色。** 现在卡片用了边框加阴影加底色三重区分，减到一重。
- **字号阶梯收敛**为 11/12/13/16 四级，去掉中间值。
- **一屏一个主操作。** 详情页的「应用」是唯一 primary 按钮，其余为 secondary 或纯文字按钮。
- **状态色只用于状态本身**，不用于装饰；成功态用完即隐，不常驻。
- **动效**只保留 150ms 以内的 opacity/transform 过渡，不做位移动画。
- 保持 `prefers-color-scheme` 兼容（现有 tokens 已含深色变量则沿用）。

## 6. 测试先行

按既有约定，先写测试再实现。

**单元（vitest）**
- `icons/agents.test.tsx`：每个 auto Agent 都有映射；未知 ID 返回兜底图标；图标 `aria-hidden`。
- `AgentManageRow.test.tsx`：改造为纯展示行——断言不再渲染表单控件；点击触发导航回调。
- `AgentDetailPage.test.tsx`：从 `AgentManageRow` 平移「探测通过才能应用」「改 Key 作废结论」「应用后显示重启指引」「Key 不入浏览器存储」四条。
- `ProvidersPage.test.tsx` / `ProfilesPage.test.tsx`：列表渲染、空态、哪些 Agent 在用某 Provider。

**e2e（Playwright）**
- 侧边栏四项逐一点击后 URL 与标题正确——直接覆盖第 4 点的 bug。
- 总览点某 Agent 进详情，改配置后返回总览看到新指向。
- 列表长度不因操作而变化（回归第 3 点的动机）。
- 三个视口下无横向溢出（沿用现有 `expectNoHorizontalOverflow`）。

覆盖率门禁不变：`src/api`、`src/state` ≥85%。

## 7. 实施顺序

1. **首屏减负**：移除 `EnvironmentSummary` 与 `overview-notice` 横幅，版本提示降级为行内标记，删除重复文案。收益最直接且不依赖其他改造，先做。
2. 图标集 + 单元测试（独立，无依赖）
3. 侧边栏 bug 修复 + `/providers`、`/profiles` 两页（解掉用户当前就能碰到的问题）
4. `/agents/:agentId` 详情页，`AgentManageRow` 瘦身
5. 视觉规范收敛（第 5 节）
6. 全量测试 + 真实服务截图验证

每完成一步跑 `npm run build` 与相关测试。第 1、4、6 步各截图一次确认，再推进下一步——第 1 步要用截图验证首屏是否真的能完整显示五个 Agent。

### 需要同步的既有测试

移除 `EnvironmentSummary` 会让 `wizard.spec.ts` 中断言「开发环境已就绪」的两处失败（上一轮已经踩过一次）。这两处断言的**意图**是「向导完成后进入总览」，改为断言总览的 Agent 列表出现，而不是删掉断言。

## 8. 风险

- **第 3 步动的是刚落地的 `AgentManageRow`**，它的四条行为约束有测试保护，平移时必须让测试跟着搬而不是删掉。
- **侧边栏改动会影响现有 e2e**：`wizard.spec.ts` 有从侧边栏进入向导步骤的路径，需同步更新。
- **`/profiles` 页涉及 Key**：模板可携带 Key，页面只能显示 `hasKey` 布尔，绝不能回显 Key 本身。
- 商标使用限制见第 0 节，新增图标时逐个确认许可。
